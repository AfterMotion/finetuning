### 3.3 Density, Spatial & Layout Tokens
- **4px Spatial Scale**: `--space-0` (0px) to `--space-32` (128px) in 4px multiples (`--space-1` = 4px, `--space-2` = 8px, `--space-4` = 16px, `--space-6` = 24px, `--space-8` = 32px, etc.).
- **Density Modes**:
  - `.density-comfortable`: Body font 16px, card padding 24px, table rows 48px, component padding Y 12px / X 16px. *(Default for Marketing & Case Studies)*
  - `.density-compact`: Body font 14px, card padding 16px, table rows 36px, component padding Y 6px / X 12px. *(Default for Admin Tables & Telemetry)*
- **Breakpoints**: `--breakpoint-xs` (375px), `--breakpoint-sm` (640px), `--breakpoint-md` (768px), `--breakpoint-lg` (1024px), `--breakpoint-xl` (1280px), `--breakpoint-2xl` (1536px).
- **Z-Index Layering**: `--z-base` (0) < `--z-raised` (10) < `--z-dropdown` (1000) < `--z-sticky` (1100) < `--z-drawer` (1200) < `--z-modal` (1300) < `--z-popover` (1400) < `--z-toast` (1500).
- **Radii**: `--radius-sm` (4px), `--radius-md` (8px), `--radius-lg` (12px), `--radius-xl` (16px), `--radius-full` (9999px).

## 4. Approved Logo & Imagery Rules

### 4.1 Immutable Logo Facts vs. Proposed Design Choices
As codified in [docs/BRAND_GUIDELINES.md](file:///d:/my-project/FineTuning\finetuning.com.bd\docs\BRAND_GUIDELINES.md#L81-L108):

| Attribute | Classification | Authoritative Specification |
| :--- | :---: | :--- |
| **Emblem Coordinate Geometry** | Observed Fact | `viewBox="0 0 2400 1758"`. Precision needle tapers from `(978, 53)` down to coordinate `(1200, 1495)`. |
| **Hex Colors in Vector Mark** | Observed Fact | Wings/Needle: `#F09320` (Solar Amber). Resonant Cradle: `#4694B1` (Nordic Teal). |
| **Tittles on Wordmark** | Observed Fact | Flared serif `FineTuning` lettering has distinct Nordic Teal `#4694B1` circular dots on both lowercase `i`s. |
| **Descriptor Text** | Observed Fact | "Advertising Agency" rendered in tracked Nordic Teal uppercase sans-serif (`letter-spacing: 0.28em`). |
| **Clear Space Requirement** | Proposed Standard | Exclusion perimeter $X = 443$ SVG units (needle apex width). Minimum 24px padding on mobile, 48px on desktop, 12mm on print. |
| **Minimum Digital Dimensions** | Proposed Standard | 160px width for horizontal lockup; 24px width for isolated vector emblem mark. |
| **Text Contrast Adaptation** | Proposed Standard | High-contrast dark teal `#2B5E70` introduced for text on white canvas (replaces unreadable `#4694B1` in body text). |

### 4.2 Approved Logo Variants & Placement
1. **Primary Horizontal Lockup**: Full lockup with SVG mark + `FineTuning` flared serif wordmark + descriptor. Used on white, neutral slate, or dark obsidian backgrounds.
2. **Centered Vertical Lockup**: Large emblem centered above the wordmark. Used on stage backdrops, presentation title cards, and exhibition wayfinding.
3. **Isolated Emblem Mark**: Symmetrical needle, dual "F" wings, and cradle basin without typography. Used as site favicon, app launcher icon, avatar badges, and technical console watermark.
4. **Monochrome / Single-Tone**: All-white (`#FFFFFF`) on dark backdrops; all-obsidian (`#070D18`) on light backdrops. Permitted only when full color printing is technically unavailable.

### 4.3 Prohibited Logo Practices (Anti-Patterns)
- ❌ **NEVER** alter the color of the central needle (it must always remain Solar Amber `#F09320`).
- ❌ **NEVER** place white text over Solar Amber buttons (violates WCAG AA at 2.36:1). Always use Midnight Obsidian `#070D18` text (8.24:1 AAA).
- ❌ **NEVER** distort, stretch, or alter the 2400:1758 aspect ratio.
- ❌ **NEVER** remove the Nordic Teal cradle basin or detach the needle from the flight wings.
- ❌ **NEVER** encroach upon the $X = 443$ SVG units clear space boundary with layout text or borders.

### 4.4 Imagery & Photography Standards
1. **Authenticity Over Stock**: Zero generic American/European stock photography. All imagery must depict real event staging in Bangladesh (e.g., Radisson Blu Chattogram, ICCB Dhaka, Navy Convention Centre, Bargee Lake Valley Rangamati).
2. **Aspect Ratios**: 16:9 for hero showcases and editorial cards; 4:3 or 1:1 for technical equipment and stage schematics.
3. **Optimized Delivery**: High-resolution WebP format with quality factor 85, lazy loading (`loading="lazy"`), and explicit width/height tags to eliminate Cumulative Layout Shift (CLS).
4. **Color Treatment**: True-to-life stage lighting with deep black levels (`#070D18`) and vibrant LED backdrops. No muddy Instagram-style filters.

## 7. Target Tech Stack & Architecture Options

To honor the approved design system while ensuring long-term maintainability, the technical stack is structured in three graduated tiers:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                         TARGET ARCHITECTURE TIERS                           │
├─────────────────────────────────────────────────────────────────────────────┤
│ TIER 1: ZERO-DEPENDENCY PURE STATIC (Current Baseline)                      │
│ - Semantic HTML5 + Vanilla CSS Custom Properties (tokens.css, themes.css)   │
│ - Pure Vanilla ES6 JavaScript (demo-shell.js, app.js)                       │
│ - Zero build tools, instant GitHub Pages / CDN compatibility                │
├─────────────────────────────────────────────────────────────────────────────┤
│ TIER 2: TAILWIND CSS v3 / v4 (Immediate Developer Ergonomics)               │
│ - Bound to tokens/tailwind.config.cjs                                       │
│ - Utilities mapped to CSS variables (e.g., bg-brand-amber-500, text-fg-*)   │
│ - Dark mode managed via class="[data-theme='dark']"                         │
├─────────────────────────────────────────────────────────────────────────────┤
│ TIER 3: MODERN JAMSTACK FRAMEWORK (Future Production Scale)                │
│ - Next.js (App Router) or Astro 4.x                                         │
│ - Server-Side Rendering (SSR) for Case Studies SEO                          │
│ - API routes for WhatsApp webhook automation and quotation PDF generation   │
```

### Conflict 1: Registered HQ Address vs. Technical Operations Base
- **The Issue**: [README.md](file:///d:/my-project/FineTuning\finetuning.com.bd\README.md#L5) and [docs/brand-activities-overview.md](file:///d:/my-project/FineTuning\finetuning.com.bd\docs\brand-activities-overview.md#L6) state the address as:

- **Citations**: `docs/brand-activities-overview.md` §1.1 vs. `docs/BRAND_GUIDELINES.md` §1.1.
- **Authoritative Resolution**: In commercial event staging in Bangladesh, firms frequently maintain a commercial retail desk (Kajir Dewri) alongside a large industrial staging warehouse and fleet yard (Nasirabad), and an executive liaison suite (Gulshan-2).  
  **Resolution Rule**: Corporate footers must list both:  
  *“Registered Commercial Office: Shop 01, CDA Market, Kajir Dewri, Ctg • Technical Staging Base: Nasirabad, Ctg • Dhaka Hub: Gulshan-2”*. *(Flagged for final user confirmation; no brand change required).*

### Conflict 2: Solar Amber Button Text Contrast (Obsidian vs. White)
- **The Issue**: Earlier design templates and some legacy web drafts occasionally featured white text on Solar Amber buttons. White text on `#F09320` yields a contrast ratio of only **2.36:1**, failing WCAG AA (requires 4.5:1).
- **Citations**: [docs/BRAND_GUIDELINES.md](file:///d:/my-project/FineTuning\finetuning.com.bd\docs\BRAND_GUIDELINES.md#L460-L463) §7.1 and [docs/DESIGN_SYSTEM.md](file:///d:/my-project/FineTuning\finetuning.com.bd\docs\DESIGN_SYSTEM.md#L94-L98) §3.2.
- **Authoritative Resolution**: Strict brand mandate: **Text on Solar Amber (`#F09320`) buttons MUST ALWAYS be Midnight Obsidian (`#070D18`)**, achieving **8.24:1 AAA contrast**. White text on amber is strictly forbidden across all public websites and admin consoles.

### Conflict 3: Nordic Teal Contrast on Light Canvases
- **The Issue**: Raw logo teal `#4694B1` achieves only **3.43:1 contrast** on pure white canvas (fails WCAG AA for normal body copy).
- **Citations**: [docs/BRAND_GUIDELINES.md](file:///d:/my-project/FineTuning\finetuning.com.bd\docs\BRAND_GUIDELINES.md#L464-L466) §7.1 and [tokens/tokens.css](file:///d:/my-project/FineTuning\finetuning.com.bd\tokens\tokens.css#L32-L33).
- **Authoritative Resolution**: Raw `#4694B1` is restricted to graphic elements, icons, non-text borders, and dark backgrounds (where it achieves 5.68:1 AA). For body text, links, and text-based badges on light surfaces, the system strictly mandates `--color-teal-700` (`#2B5E70`, **7.15:1 AAA**) or `--color-teal-800` (`#1C4453`, **10.49:1 AAA**).

### Conflict 4: Wordmark Flared Serifs vs. Digital Web Typography
- **The Issue**: The supplied raster wordmark (`FineTuning`) features bespoke flared serifs, which could be misconstrued as a mandate for serif body typography.
- **Citations**: [docs/BRAND_GUIDELINES.md](file:///d:/my-project/FineTuning\finetuning.com.bd\docs\BRAND_GUIDELINES.md#L302-L315) §4.1 and [docs/DESIGN_SYSTEM.md](file:///d:/my-project/FineTuning\finetuning.com.bd\docs\DESIGN_SYSTEM.md#L160-L177).
- **Authoritative Resolution**: Flared serifs belong exclusively to the official vector wordmark asset. All digital user interfaces, body copy, headings, and data consoles must utilize `Outfit` (Primary Sans), `Syne` (Display Sans), and `JetBrains Mono` (Monospace).

### Conflict 5: Token Single Source of Truth (`tokens/` vs. `assets/`)
- **The Issue**: Two sets of token files exist in the repository: `tokens/design-tokens.json` & `tokens/tokens.css`, alongside `assets/design-tokens.json` & `assets/design-tokens.css`.
- **Citations**: [docs/DESIGN_SYSTEM.md](file:///d:/my-project/FineTuning\finetuning.com.bd\docs\DESIGN_SYSTEM.md#L10-L24) §1.
- **Authoritative Resolution**: `tokens/` is the authoritative single source of truth for all human and machine consumers. The files in `assets/` are generated export mirrors produced by `.claude/skills/brand/scripts/sync-brand-to-tokens.cjs`. Build tools must always import from `tokens/tokens.css` and `tokens/themes.css`.

### Conflict 6: Missing `AGENTS.md` File
- **The Issue**: The user prompt specifically asked to "Also read AGENTS.md", but no such file exists in the repository.
- **Citations**: Workspace filesystem inventory.
- **Authoritative Resolution**: Acknowledge the absence of `AGENTS.md` without inventing arbitrary rules.
